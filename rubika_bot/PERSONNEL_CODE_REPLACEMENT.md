# انتخاب جایگزین بر اساس کد پرسنلی و سمت

## 🎯 تغییرات اعمال شده

### قبل:
- لیستی از افراد بخش/سازمان نمایش داده می‌شد
- کاربر روی نام کلیک می‌کرد
- امکان اشتباه در انتخاب وجود داشت

### بعد:
- کاربر **کد پرسنلی** جایگزین را وارد می‌کند
- سیستم **سمت (Position)** را چک می‌کند
- اطلاعات فرد نمایش داده می‌شود
- کاربر تایید می‌کند ✅

## 🔄 فرایند جدید

### مرحله 1: درخواست کد پرسنلی

```
👤 انتخاب جایگزین

📌 سمت شما: کارشناس اداری

🔍 لطفاً کد پرسنلی جایگزین خود را وارد کنید:

⚠️ توجه: جایگزین باید هم‌سمت شما باشد

مثال: 12345

💡 یا از دکمه زیر برای انصراف استفاده کنید:

❌ انصراف
```

### مرحله 2: ورود کد پرسنلی

کاربر کد پرسنلی را تایپ می‌کند، مثلاً: `12345`

### مرحله 3: نمایش اطلاعات و تایید

#### سناریو 1: هم‌سمت (همه چیز OK)

```
✅ جایگزین یافت شد

👤 نام: علی احمدی
📌 سمت: کارشناس اداری
🏢 بخش: اداری

❓ آیا این فرد صحیح است؟

✅ بله، تایید   ❌ خیر، اصلاح
🔙 انصراف
```

#### سناریو 2: سمت متفاوت (هشدار)

```
⚠️ هشدار: سمت متفاوت

👤 نام: محمد رضایی
📌 سمت شما: کارشناس اداری
📌 سمت جایگزین: کارشناس فنی

❓ آیا مطمئن هستید که این فرد را به عنوان جایگزین انتخاب می‌کنید؟

✅ بله، تایید   ❌ خیر، اصلاح
🔙 انصراف
```

## ✅ مزایا

### 1. دقت بالا
- کد پرسنلی یکتا است
- احتمال اشتباه به حداقل می‌رسد

### 2. چک خودکار سمت
- سیستم خودکار سمت را بررسی می‌کند
- در صورت تفاوت، هشدار می‌دهد

### 3. تایید قبل از ثبت
- کاربر اطلاعات را می‌بیند
- می‌تواند اصلاح کند

### 4. امنیت بیشتر
- نمی‌تواند خودش را انتخاب کند
- کاربران غیرفعال نمایش داده نمی‌شوند

## 📝 نکات مهم

### 1. کد پرسنلی باید یکتا باشد
در دیتابیس، فیلد `personnel_code` باید `unique=True` باشد.

```python
class UserProfile(models.Model):
    personnel_code = models.CharField(
        max_length=50, 
        unique=True,  # ✅ مهم
        blank=True, 
        null=True
    )
```

### 2. همه کاربران باید کد پرسنلی داشته باشند
اگر کاربری کد پرسنلی ندارد:
- نمی‌تواند به عنوان جایگزین انتخاب شود
- خودش هم نمی‌تواند جایگزین انتخاب کند

### 3. سمت (Position) مهم است
- اولویت با هم‌سمتی است
- اما اگر لازم باشد، سمت متفاوت هم قابل قبول است (با هشدار)

# قابلیت درخواست مرخصی از طریق ربات روبیکا

## نمای کلی

این feature به کاربران اجازه می‌دهد که درخواست مرخصی خود را به صورت کامل از طریق ربات روبیکا ثبت کنند. فرایند به صورت مرحله‌ای (step-by-step) انجام می‌شود و تمام اطلاعات لازم از کاربر دریافت می‌شود.

## مدل‌های استفاده شده

### LeaveRequestState
مدل جدید برای ذخیره وضعیت فرایند درخواست مرخصی کاربران:

```python
class LeaveRequestState(models.Model):
    rubika_user = OneToOneField(RubikaUser)  # کاربر روبیکا
    step = CharField(max_length=50)           # مرحله فعلی
    data = JSONField()                        # داده‌های جمع‌آوری شده
    started_at = DateTimeField()             # زمان شروع
    updated_at = DateTimeField()             # زمان به‌روزرسانی
```

**مراحل (steps):**
- `idle`: حالت اولیه / هیچ فرایندی در جریان نیست
- `leave_type`: انتخاب نوع مرخصی
- `date`: وارد کردن تاریخ مرخصی
- `shift_type`: انتخاب نوع شیفت
- `replacement`: انتخاب جایگزین (فقط برای مرخصی استحقاقی)
- `hourly_times`: وارد کردن ساعات (فقط برای مرخصی ساعتی)
- `description`: وارد کردن توضیحات
- `confirm`: تایید نهایی و ثبت درخواست

## فرایند کامل درخواست مرخصی

### 1. شروع فرایند
کاربر روی دکمه **"🏖️ درخواست مرخصی"** کلیک می‌کند.

**شرایط:**
- کاربر باید به حساب کاربری خود متصل باشد (`user.user != None`)
- در غیر این صورت، پیام خطا نمایش داده می‌شود

### 2. انتخاب نوع مرخصی
کاربر یکی از انواع مرخصی را انتخاب می‌کند:
- 📅 **مرخصی استحقاقی** (`regular`): نیاز به انتخاب جایگزین دارد
- ❌ **غیبت** (`absence`): بدون نیاز به جایگزین
- ⏰ **مرخصی ساعتی** (`hourly`): نیاز به ساعات شروع و پایان
- 🏥 **مرخصی استعلاجی** (`sick_leave`): بدون نیاز به جایگزین

### 3. وارد کردن تاریخ
کاربر تاریخ مرخصی را به فرمت شمسی وارد می‌کند:

**فرمت قابل قبول:**
- `1403/09/15`
- `1403-09-15`

**Validation:**
- تاریخ باید معتبر باشد
- تاریخ نباید در گذشته باشد
- در صورت خطا، پیام راهنما نمایش داده می‌شود

### 4. انتخاب نوع شیفت
کاربر نوع شیفت خود را انتخاب می‌کند:
- روزکار اول (`day`)
- روزکار دوم (`day2`)
- عصرکار اول (`evening`)
- عصرکار دوم (`evening2`)
- شبکار اول (`night`)
- شبکار دوم (`night2`)

### 5. مراحل اختیاری (بسته به نوع مرخصی)

#### 5.1. انتخاب جایگزین (فقط برای مرخصی استحقاقی)
- لیست کاربران همان بخش نمایش داده می‌شود
- کاربر یکی را انتخاب می‌کند
- حداکثر 10 نفر نمایش داده می‌شود

#### 5.2. وارد کردن ساعات (فقط برای مرخصی ساعتی)
کاربر ساعات شروع و پایان را وارد می‌کند:

**فرمت:**
- `08:00-12:00`
- `08:00 - 12:00`

**Validation:**
- فرمت ساعت باید صحیح باشد
- ساعت پایان باید بعد از ساعت شروع باشد
- تعداد ساعات به صورت خودکار محاسبه می‌شود

### 6. وارد کردن توضیحات
کاربر می‌تواند توضیحات اختیاری وارد کند:
- برای رد کردن این مرحله: `رد`، `skip`، `pass`، `-`

### 7. نمایش خلاصه و تایید نهایی
خلاصه کاملی از اطلاعات وارد شده نمایش داده می‌شود:
- نوع مرخصی
- تاریخ (شمسی)
- نوع شیفت
- ساعات (در صورت مرخصی ساعتی)
- جایگزین (در صورت مرخصی استحقاقی)
- توضیحات

کاربر می‌تواند:
- ✅ **تایید و ثبت**: درخواست در دیتابیس ثبت می‌شود
- ❌ **انصراف**: فرایند لغو می‌شود

### 8. ثبت در دیتابیس
اطلاعات به صورت زیر در مدل `ShiftReport` ثبت می‌شود:

```python
leave_request = ShiftReport()
leave_request.user = user.user
leave_request.leave_type = data['leave_type']
leave_request.shift_date = datetime.fromisoformat(data['date']).date()
leave_request.shift_type = data['shift_type']
leave_request.work_group = profile.group or 'نامشخص'
leave_request.crate_by = profile
leave_request.description = data.get('description')

# Set status based on leave type
if leave_type in ['absence', 'sick_leave', 'hourly']:
    leave_request.status = 'pending_approval'
    leave_request.replacement_approved = True
else:
    leave_request.status = 'pending_replacement'

leave_request.save()
```

## Handler های پیاده‌سازی شده

### Button Handlers
- `_start_leave_request`: شروع فرایند
- `_cancel_leave_request`: لغو فرایند
- `_handle_leave_type_selection`: انتخاب نوع مرخصی
- `_handle_shift_type_selection`: انتخاب نوع شیفت
- `_handle_replacement_selection`: انتخاب جایگزین
- `_handle_leave_confirmation`: تایید نهایی

### Text Input Handlers
- `_handle_leave_request_input`: مدیریت ورودی متنی
- `_process_date_input`: پردازش تاریخ
- `_process_hourly_times_input`: پردازش ساعات
- `_process_description_input`: پردازش توضیحات

### Helper Methods
- `_ask_for_replacement`: درخواست انتخاب جایگزین
- `_ask_for_hourly_times`: درخواست ساعات
- `_ask_for_description`: درخواست توضیحات
- `_show_leave_summary`: نمایش خلاصه
- `_save_leave_request`: ذخیره در دیتابیس

## نکات مهم

### 1. State Management
هر کاربر یک `LeaveRequestState` دارد که وضعیت فعلی و داده‌های جمع‌آوری شده را ذخیره می‌کند.

### 2. Validation
تمام ورودی‌ها validate می‌شوند:
- تاریخ باید معتبر و در آینده باشد
- ساعات باید فرمت صحیح داشته باشند
- جایگزین باید از همان بخش باشد

### 3. Error Handling
در صورت بروز خطا:
- پیام خطای واضح نمایش داده می‌شود
- کاربر می‌تواند مجدداً تلاش کند
- در صورت خطای جدی، لاگ ثبت می‌شود

### 4. Cancellation
کاربر در هر مرحله می‌تواند با دکمه **"❌ انصراف"** فرایند را لغو کند.

### 5. Integration با سیستم موجود
- درخواست‌های ثبت شده در جدول `ShiftReport` ذخیره می‌شوند
- فرایند تایید موجود (جایگزین → مدیر) حفظ شده است
- کاربر می‌تواند وضعیت درخواست را از پنل وب پیگیری کند

## نصب و راه‌اندازی

### 1. اجرای Migration
```bash
python manage.py migrate rubika_bot
```

### 2. Admin Panel
مدل `LeaveRequestState` در پنل ادمین قابل مشاهده است:
- مشاهده state کاربران
- بررسی داده‌های جمع‌آوری شده
- حذف state های قدیمی (در صورت نیاز)

### 3. تست
برای تست کامل:
1. به ربات متصل شوید
2. روی دکمه "درخواست مرخصی" کلیک کنید
3. فرایند را کامل کنید
4. بررسی کنید که درخواست در دیتابیس ثبت شده است

## پیام‌های خطا

### کاربر متصل نیست
```
⚠️ برای ثبت درخواست مرخصی، ابتدا باید به حساب کاربری خود متصل شوید.

🔗 از دکمه "اتصال" استفاده کنید.
```

### تاریخ نامعتبر
```
❌ فرمت تاریخ نامعتبر است. لطفاً به فرمت زیر وارد کنید:

1403/09/15

یا 1403-09-15
```

### ساعت نامعتبر
```
❌ فرمت ساعت نامعتبر است. لطفاً به فرمت زیر وارد کنید:

08:00-12:00
```

### جایگزین یافت نشد
```
⚠️ کاربر جایگزینی در بخش شما یافت نشد.

لطفاً با مدیر خود تماس بگیرید.
```

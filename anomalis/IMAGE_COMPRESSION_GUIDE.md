# راهنمای فشرده‌سازی تصاویر آنومالی

## مشکل
حجم زیاد تصاویر آپلود شده توسط کاربران باعث پر شدن فضای ذخیره‌سازی سرور می‌شود.

## راه‌حل پیاده‌سازی شده
سیستم فشرده‌سازی دو لایه‌ای برای کاهش حجم تصاویر:

### 1. فشرده‌سازی در سمت کلاینت (Frontend)
- **کتابخانه**: `browser-image-compression`
- **زمان اجرا**: قبل از ارسال فرم به سرور
- **تنظیمات**:
  - حداکثر حجم: 1 مگابایت
  - حداکثر ابعاد: 1920 پیکسل
  - کیفیت: 85%
  - فرمت خروجی: JPEG

**مزایا**:
- کاهش زمان آپلود برای کاربران
- کاهش مصرف پهنای باند سرور
- تجربه کاربری بهتر با نمایش پیام "در حال فشرده‌سازی..."

### 2. فشرده‌سازی در سمت سرور (Backend)
- **کتابخانه**: `Pillow` (Python)
- **زمان اجرا**: قبل از ذخیره در دیتابیس (در متد `save` مدل `Anomaly`)
- **تنظیمات**:
  - حداکثر حجم: 1 مگابایت
  - حداکثر ابعاد: 1920 پیکسل
  - کیفیت: 85% (با امکان کاهش تا 20% برای رسیدن به حجم دلخواه)
  - فرمت خروجی: JPEG

**مزایا**:
- اطمینان از فشرده‌سازی حتی اگر کلاینت آن را انجام نداده باشد
- امکان مدیریت تصاویر آپلود شده از API یا Admin Panel
- تبدیل خودکار فرمت‌های RGBA به RGB

## فایل‌های تغییر یافته

### 1. `anomalis/utils.py` (جدید)
توابع کمکی برای فشرده‌سازی و اعتبارسنجی تصاویر:
- `compress_image()`: فشرده‌سازی تصویر با تنظیمات قابل تغییر
- `validate_image_file()`: اعتبارسنجی نوع و حجم فایل

### 2. `anomalis/models.py`
- اضافه شدن متد `save()` به مدل `Anomaly` برای فشرده‌سازی خودکار
- Import تابع `compress_image` از `utils`

### 3. `anomalis/forms.py`
- بروزرسانی متد `clean_image()` در فرم `AnomalyForm`
- استفاده از `validate_image_file()` برای اعتبارسنجی
- افزایش محدودیت حجم از 5MB به 10MB (قبل از فشرده‌سازی)

### 4. `templates/anomalis/new-anomalie.html`
- اضافه شدن کتابخانه `browser-image-compression`
- پیاده‌سازی تابع `compressImage()` در JavaScript
- فشرده‌سازی خودکار قبل از ارسال فرم
- نمایش پیام "در حال فشرده‌سازی..." به کاربر

## محدودیت‌ها

### قبل از فشرده‌سازی
- حداکثر حجم آپلود: 10 مگابایت
- فرمت‌های مجاز: JPG, JPEG, PNG, GIF, WebP

### بعد از فشرده‌سازی
- حجم نهایی: معمولاً کمتر از 1 مگابایت
- فرمت نهایی: JPEG (بهینه برای فضای ذخیره‌سازی)

## نحوه استفاده

### برای کاربران
1. فایل تصویر را در فرم انتخاب کنید (کشیدن و رها کردن یا انتخاب دستی)
2. سیستم به طور خودکار تصویر را قبل از ارسال فشرده می‌کند
3. پیام "در حال فشرده‌سازی..." نمایش داده می‌شود
4. فرم ارسال می‌شود

### برای توسعه‌دهندگان
تنظیمات فشرده‌سازی قابل تغییر است:

**در Frontend** (`new-anomalie.html`):
```javascript
const options = {
  maxSizeMB: 1,              // تغییر حجم نهایی
  maxWidthOrHeight: 1920,    // تغییر ابعاد
  initialQuality: 0.85       // تغییر کیفیت
};
```

**در Backend** (`models.py`):
```python
self.image = compress_image(
    self.image, 
    max_size_mb=1,      # تغییر حجم نهایی
    quality=85,         # تغییر کیفیت
    max_dimension=1920  # تغییر ابعاد
)
```

## تست کردن

### 1. تست فشرده‌سازی Frontend
- تصویری با حجم بالای 2MB انتخاب کنید
- Console مرورگر را باز کنید
- پیام‌های "حجم اصلی تصویر" و "حجم فشرده شده" را مشاهده کنید

### 2. تست فشرده‌سازی Backend
- تصویری را از طریق Django Admin Panel آپلود کنید
- حجم نهایی فایل در مسیر `media/anomalies/` را بررسی کنید

## بهبودهای آینده (اختیاری)

1. **نمایش Progress Bar**: نمایش درصد پیشرفت فشرده‌سازی
2. **تنظیمات کاربر**: امکان انتخاب کیفیت توسط کاربر
3. **Lazy Loading**: بارگذاری تنبل تصاویر برای بهبود سرعت
4. **WebP Support**: استفاده از فرمت WebP برای فشرده‌سازی بهتر
5. **Thumbnail Generation**: ایجاد خودکار تصاویر کوچک برای لیست‌ها

## نکات مهم

- **سازگاری با مرورگرها**: کتابخانه `browser-image-compression` در تمام مرورگرهای مدرن کار می‌کند
- **Fallback**: اگر فشرده‌سازی Frontend با خطا مواجه شود، فایل اصلی ارسال می‌شود
- **امنیت**: اعتبارسنجی کامل در Backend انجام می‌شود
- **کارایی**: استفاده از Web Worker در Frontend برای جلوگیری از مسدود شدن UI
- **سازگاری با موبایل**: سیستم در دستگاه‌های موبایل نیز به خوبی کار می‌کند

## تماس با پشتیبانی
در صورت بروز مشکل، لاگ‌های مربوط به فشرده‌سازی را در Console مرورگر بررسی کنید.
